# WebSight 보안·역할·화면 개선 실행 계획

**목표:** 관리자와 사용자가 안전하게 업무를 처리하고 조회자는 공개 통계를 확인할 수 있도록 개선한다.

**구조:** Next.js 앱과 PostgreSQL을 Vercel과 학교 34번 서버에서 공통으로 사용한다. 인증·권한 검사는 서버에서 수행하고, 운영 데이터와 세션은 영구 저장한다. 현재 파일 스토어는 개발 및 데이터 이전 용도로만 취급하며 운영에서 조용히 대체 저장하지 않는다.

**기술:** 기존 Next.js, TypeScript, PostgreSQL. 인증 라이브러리 및 비밀번호 해싱 방식은 현재 버전 호환성과 보안 유지보수 상태를 확인해 선택한다.

**기준:** 사용자 요청 및 2026-11-04 현재 코드 검토. 아래 가정은 승인 시 함께 확인한다.

## 역할과 가정

- 관리자: 비밀번호로 로그인하고 사용자 계정, 키워드, 담당 범위, 지식과 설정을 관리한다. 최초 관리자 이메일과 초기 비밀번호는 환경변수로 설정한다. 초기화 후 환경변수 변경이 기존 비밀번호를 덮어쓰지 않는다. 관리자는 현재 비밀번호를 확인하고 새 비밀번호로 변경한다.
- 사용자: 관리자가 만든 계정으로 로그인하고 담당한 네이버 지식인 질문을 조회하고 답변 초안을 작성·수정·복사한다. 답변은 네이버에서 직접 게시한다. 자동 게시는 구현하지 않는다.
- 조회자: 로그인 없이 공개 혜전대학교 키워드 통계를 본다. 검색 결과 건수는 검색 API가 제공하는 결과 수이며 검색 횟수 또는 실제 노출·조회 횟수로 표시하지 않는다.
- 사용자 계정은 관리자가 초기 비밀번호를 지정하고 안전한 별도 경로로 전달한다. 관리자 암호 변경과 사용자 암호 변경·관리자에 의한 초기화 기능을 제공한다. 이메일 인증 및 메일 발송은 이번 범위에 포함하지 않는다.

## 완료 조건과 위험 확인

- 비인증자와 다른 역할의 사용자는 보호된 페이지와 API에 직접 접근하거나 변경할 수 없다. 담당 범위 밖의 지식인 질문·초안도 접근할 수 없다.
- 비밀번호 원문은 저장·로그·Git에 남지 않는다. 계정 비활성화와 비밀번호 변경 시 기존 세션을 폐기한다.
- 데이터베이스 장애나 설정 누락 시 성공으로 가장하지 않는다. 기존 데이터 이전은 백업과 검증 후 진행한다.
- Vercel과 학교 서버의 환경변수, DB 마이그레이션, TLS·프록시·백업·작업 스케줄러를 문서화한다. 실제 서버 구성은 접속 전까지 확인된 것으로 가정하지 않는다.
- 개발용 인증과 공개 변경 API를 운영에 배포하지 않는다. 데이터 이전과 배포는 운영 환경 확인 및 별도 배포 승인 후 진행한다.

## 1. 현황·운영 데이터 조사와 보안 격리

**대상:** `src/app`, `src/auth`, `src/db`, `db`, `deploy`, `vercel.json`, 테스트 및 환경변수 예시.

- [ ] 모든 화면·API와 읽기/쓰기 경로를 역할별 목록으로 작성한다. 공개 통계만 익명 접근 대상으로 지정한다.
- [ ] Vercel과 학교 서버의 DB 사용 가능 여부 및 기존 데이터 위치를 확인한다. 비밀값은 출력하거나 저장하지 않는다.
- [ ] 현재 공개된 개발 인증과 무인증 변경 경로를 재현하는 통합 테스트를 작성한다. 실제 운영 사이트에는 변경 요청을 보내지 않는다.
- [ ] 운영 중인 배포의 위험을 안내한다. 임시 접근 제한 등 운영 조치는 사용자와 범위를 확인한 후 수행한다.

**검증:** 접근 목록과 실패를 재현한 테스트가 준비되어 있고, 기존 사용자·담당자·초안·설정·통계의 이전 대상과 출처가 기록된다.

## 2. 영구 저장과 이전

**대상:** `db/` 마이그레이션, `src/db/`, 수집 작업 및 데이터 이전 도구.

- [ ] 계정, 세션, 담당 범위, 설정, 키워드, 지식, 질문·초안을 PostgreSQL에 일관되게 저장한다. 기존 순위 테이블과 연결하고 필요한 제약조건·인덱스를 추가한다.
- [ ] 마이그레이션은 기존 테이블과 데이터에 영향을 주지 않도록 작성하고 빈 DB와 기존 스키마에서 검증한다. DB 자격증명은 최소 권한으로 분리한다.
- [ ] 기존 파일 데이터의 백업·검사·가져오기·건수 대조 절차를 마련한다. 중복 실행 시 중복 생성되지 않도록 한다. 세션과 개발용 계정은 이전하지 않는다.
- [ ] 운영에서는 DB 연결 실패 시 임시 파일로 성공 처리하지 않고 명확한 오류를 반환한다.

**검증:** 재시작과 복수 인스턴스에서 변경 사항이 유지되고, 동시 변경·DB 장애·이전 재실행 테스트가 통과한다.

## 3. 로그인·사용자 관리·권한

**대상:** `src/auth/`, `src/app/api/auth/`, 관리자 사용자 관리 화면 및 API, 보호된 페이지·API.

- [ ] 초기 관리자 환경변수는 최초 계정이 없을 때만 사용하고 초기 비밀번호 변경을 요구한다. 초기값 누락 또는 취약한 비밀번호는 안전하게 거부한다.
- [ ] 비밀번호를 안전한 단방향 해시로 저장하고 로그인 실패 제한, 안전한 쿠키, 세션 만료·폐기, 로그아웃을 구현한다. 서버 측에서 요청 위조 방어도 적용한다.
- [ ] 관리자 사용자 생성·활성화·비활성화·비밀번호 초기화와 본인 비밀번호 변경을 구현한다. 화면에 비밀번호를 다시 표시하지 않는다.
- [ ] 관리자, 사용자, 익명 조회자 권한을 모든 화면과 API에서 서버 측으로 검사한다. 설정·수집·담당자·지식 변경은 관리자만 허용한다.
- [ ] 이메일만으로 로그인하는 개발 세션과 미구현 매직링크 경로를 제거한다.

**검증:** 초기화·변경 후 재로그인, 잘못된 암호, 로그인 제한, 권한 우회, 비활성화된 사용자, 세션 무효화 및 CSRF 테스트가 통과한다.

## 4. 지식인 업무와 통계 정확성

**대상:** `src/jobs/collect-run.ts`, `src/db/live-stats.ts`, `src/app/api/kin/`, `src/app/review/`, 관련 컴포넌트.

- [ ] 실제 등록·활성화된 키워드를 수집과 지식인 조회에 사용한다. DB에 저장한 수집 결과를 공개 통계에서도 읽는다.
- [ ] 담당 키워드·사이트 범위를 서버에서 적용하고, 사용자가 해당 질문의 답변 초안을 직접 작성·수정·저장·복사할 수 있게 한다.
- [ ] 네이버 수집 실패와 빈 결과를 구분하며 샘플을 실제 통계로 표시하지 않는다. 공개 호출에 따른 외부 API 과다 사용을 제한한다.
- [ ] 수집 일정과 보존 기간이 실제 저장·삭제 동작에 반영되도록 확인한다.

**검증:** 추가한 키워드 수집, 담당 범위 외 접근 거부, 초안 저장·복사, DB 결과 표시, API 실패와 빈 결과, 보존기간 삭제를 확인한다.

## 5. 화면 디자인과 접근성

**대상:** `src/app/layout.tsx`, `src/app/globals.css`, 통계·로그인·관리·검토 화면과 컴포넌트.

- [ ] 혜전대학교 업무 화면에 맞는 일관된 색상·글자 크기·간격과 명확한 메뉴를 적용한다. 관리자·사용자·조회자의 주요 작업을 각각 쉽게 찾게 한다.
- [ ] 통계의 수치 의미와 기준 시각을 명확히 표시하고, 지식인 질문과 답변 작성 영역을 읽기 쉽게 배치한다.
- [ ] 모바일과 데스크톱, 긴 텍스트, 빈 상태, 실패 상태, 키보드 조작과 명도 대비를 점검한다.

**검증:** 주요 화면을 실제 브라우저에서 캡처·점검하고 로그인부터 역할별 주요 작업까지 실행한다.

## 6. 종합 검증과 배포 준비

**대상:** 테스트, `package.json`, `README.md`, `deploy/`.

- [ ] 현재 동작하지 않는 lint 명령을 수정하고 테스트, lint, 타입 검사, 프로덕션 빌드를 실행한다.
- [ ] 역할별 정상·거부 흐름, DB 장애·재시작·데이터 이전, 수집 실패, 비밀번호 및 세션 폐기를 종합 검증한다.
- [ ] Vercel 환경변수와 DB 마이그레이션, 롤백 및 백업 절차를 정리한다. 비밀값은 문서나 저장소에 넣지 않는다.
- [ ] 학교 서버용 Node·PostgreSQL·프로세스 관리·스케줄러·리버스 프록시·HTTPS·백업 및 복구 절차를 작성한다. 서버 34의 실제 설치 상태 확인 후 차이를 반영한다.
- [ ] 코드와 테스트 결과를 검토할 수 있게 정리한다. GitHub 푸시, Vercel 적용, 서버 접속·이전은 각각 실행 전 구체적인 대상과 변경 내용을 제시하고 승인을 받는다.

**검증:** 자동 검사와 브라우저 검증 결과, 운영 전 필수 설정, 미해결 사항 및 복구 방법이 확인된다.

## 추가 요구: 충청권 대학 비교

- 혜전대학교, 백석문화대학교, 아주자동차대학교, 신성대학교, 연암대학교, 충남도립대학교를 비교한다. 실제 검색어는 각 대학의 공식 명칭과 동의어를 확인해 관리한다.
- 네이버 검색 API의 검색 결과 건수와 데이터랩의 상대 검색 관심도를 별도 지표로 표시한다. 상대 지수는 절대 검색량이나 홈페이지 방문·조회수가 아니다.
- 데이터랩은 요청당 최대 5개 그룹이므로 6개 대학을 서로 다른 요청에서 얻은 원시 지수를 직접 비교하지 않는다. 공통 기준 그룹을 포함한 비교 방법과 기준값 0·누락·기간 경계 처리의 타당성을 검증하고, 보정이 불가능한 경우 비교 불가로 표시한다.
- 데이터랩 권한이나 수치가 없을 때 추정값을 만들지 않는다. 응답 지연·호출 제한·캐시 및 기준 시각을 표시한다. 사용자에게 실제 홈페이지 조회수가 필요한 경우 각 대학의 분석 데이터 제공 여부를 확인한다.
