# 운영 및 서버 34 이전

이 문서는 배포 절차이며 실제 배포·DB 변경은 별도 승인 후 실행한다. 이 앱은 운영 환경에서 PostgreSQL이 필수다. `/tmp` 파일을 운영 저장소로 사용하지 않는다.

## 공통 준비

1. PostgreSQL 인스턴스와 백업·복구 방법을 확인한다. 기존 DB를 공유하면 `websight` 스키마와 별도 최소 권한 앱 계정을 사용한다. DB 관리자 권한으로 `db/001`부터 `006`까지 번호 순서로 실행한다. 애플리케이션 계정에는 이 스키마의 필요한 테이블 DML과 시퀀스 사용 권한만 부여한다.
2. `deploy/env.example`의 항목을 비밀 저장소에 설정한다. `WEBSIGHT_DATABASE_URL`은 접근 가능한 DB URL이며, 외부 네트워크에서는 서버 인증을 검증하는 TLS 연결을 사용한다. `DB_SCHEMA`는 현재 마이그레이션의 `websight`와 일치해야 한다.
3. `WEBSIGHT_ADMIN_EMAIL`, `WEBSIGHT_INITIAL_ADMIN_PASSWORD`를 설정한다. 초기 비밀번호는 15자 이상이다. 계정이 없을 때 최초 로그인 시 한 번만 생성되며, 변경 후에는 환경변수 값을 변경해도 기존 비밀번호가 바뀌지 않는다. 최초 로그인 후 새 비밀번호로 바꾸고 초기 비밀번호를 비밀 저장소에서 제거한다. 값을 Git이나 로그에 넣지 않는다.
4. `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에는 네이버 검색과 검색어 트렌드 API 권한이 있는 키를 설정한다. 다음 검색을 활성화할 경우 `KAKAO_REST_API_KEY`를 설정한다. 데이터랩 권한이 없으면 상대 관심도는 조회 불가로 표시된다.
5. 배포 전 백업과 롤백 방법을 검증한다. 기존 파일 데이터는 먼저 원본을 별도 안전한 위치에 백업한다. **신규 앱이 `websight.app_state`를 만들기 전에** `npm run import-legacy -- <백업파일경로> --apply`를 한 번 실행한다. 이미 상태가 있으면 덮어쓰지 않고 중단한다. 과거 개발용 사용자·세션·매직링크 및 예시 데이터는 가져오지 않는다. 사용자 계정은 관리자가 다시 만들고 배정한다. 기존 질문에 검색 키워드 정보가 없으면 사용자에게 자동 공개되지 않으므로 재감지하거나 관리자 검토가 필요하다.
6. `npm ci`, `npm test`, `npm run test:integration`, `npm run lint`, `npm run build`를 실행한다. 실제 PostgreSQL에서도 마이그레이션, 최초 로그인·비밀번호 변경·사용자 배정·저장과 백업 복구를 확인한다.

## Vercel

- Preview 배포는 `WEBSIGHT_PREVIEW_DATABASE_URL`에 별도 테스트 DB를 명시해야만 DB에 접근한다. 설정하지 않으면 운영 DB를 사용하지 않는다. 테스트 DB에 001~006 마이그레이션과 별도 관리자 환경변수를 설정한다.
- 프로젝트의 Production 환경변수에 위 값과 충분히 긴 무작위 `CRON_SECRET`을 설정한다. 이 값은 Vercel Cron 인증에 사용한다. 키를 저장소에 기록하지 않는다.
- `vercel.json`은 매일 UTC 21:15, 한국시간 다음 날 06:15에 정기 수집·만료 삭제를 요청한다. Vercel Hobby에서는 지정된 시각과 실제 실행 시각이 다를 수 있다. 기능의 시간 제한과 키워드 수를 운영에서 확인한다.
- 새 데이터베이스와 환경변수, 미리 검증된 마이그레이션을 준비한 뒤 배포한다. 정기 작업 로그와 `/api/health` 응답을 확인한다. 실패 시 이전 배포와 DB 백업으로 복구한다. 이전 배포로 롤백할 때 Vercel Cron 설정이 자동으로 이전 상태로 복구되는지 별도 확인한다.
- Vercel 계정과 DB에 대한 방화벽·TLS·로그인 시도 제한은 제공 서비스의 보안 기능으로 보강한다. 앱은 계정별 로그인 실패 제한을 제공하지만 분산 공격에 대한 네트워크 차원의 제한을 대신하지 않는다.

## 학교 34번 서버

- 실제 OS, Node.js 지원 버전, PostgreSQL 위치, 포트, 역방향 프록시와 인증서, 백업 정책을 먼저 확인한다. 다른 앱과 별도 경로·프로세스·DB 권한을 사용한다.
- 예시 경로는 `/opt/hju/hju-websight-monitor`, 앱 포트는 `3040`이다. 프록시가 TLS를 종료하고 앱 포트는 외부에 직접 노출하지 않도록 `127.0.0.1`에 바인딩한다. 비밀번호와 DB URL을 담은 `.env` 파일은 앱 계정만 읽을 수 있게 제한한다.
- `npm ci && npm run build` 후 프로세스 관리자로 실행한다. `deploy/cron.example`의 일일 수집과 만료 삭제를 설치한다. 서버의 시간대가 Asia/Seoul인지 확인한다. Vercel과 서버 34에서 같은 DB에 동시에 정기 수집을 켜지 않는다.
- 이전 전후에 계정·설정·키워드·질문·초안·최근 순위 건수와 표본을 대조한다. 배포 후 관리자/사용자 권한과 비로그인 접근 제한을 확인한다.
